OpenMP for Parallelization Notes

My notes on what is OpenMP and how to use it.

Reading Time5 Min Read
TopicParallelization

Introduction

OpenMP is an API that lets you turn sections of your single threaded C, C++, or Fortran code into multi-threaded code. By using this API, you don't have to start any threads and you just annotate in the code where the work begins. All threads on OpenMP have access to the same shared memory pool, so computation between machines isn't possible. There is a solution though by using the Message Passing Interface (MPI) which can start separate processes with their own memory and pass data between processes. These notes will only cover OpenMP, but just know that OpenMP and MPI are fundamental pieces to high performance compute.

OpenMP Basics

Everything in OpenMP starts with #pragma omp and the basic format is #pragma omp directive(s) clause(s). You can combine directives together, but only specific combinations will work. Clauses can be combined as well as long as the directive accepts the clause. The following are commonly used examples with a description.

  • #pragma omp parallel: Marks the section of code where every thread executes that code in parallel.
  • #pragma omp parallel for: Marks a for loop whose iterations are distributed across threads.
  • #pragma omp critical [(name)]: Blocks entire chunks of code for safely updating shared data by making other threads wait until the data is free. Name is used to identify critical regions and unnamed regions are one global lock.
  • #pragma omp atomic: A lightweight alternative to critical that protects a single memory location rather than a block of code. It utilizes hardware-level instructions to ensure a single read, write, or update operation happens indivisibly without software locking overhead.
  • #pragma omp barrier: Every thread will wait at this mark then move forward together.
  • #pragma omp single: Only one thread will run this block and other threads wait for it to finish

There are a bunch more directives, but let's move on to clauses.

  • if(expression): When evaluated to true then it will run in parallel and false will be serial.
  • num_threads(num): Sets the number of threads to run, overriding the default.
  • schedule(): Specify how loop iterations are divided among threads (dynamic, guided, runtime, or static).
  • nowait: Implicit barriers from things like #pragma omp for are now skipped with this.
  • private(variable): Thread gets its own copy of this variable, but variable is uninitialized.
  • firstprivate(variable): Same as private, but the variable is initialized with the value before the region.
  • lastprivate(variable): Same as private, but the thread that executes the final sequential iteration of a loop copies its local value back to the original variable outside the region.
  • shared(variable): Specifies one or more variables shared among all threads.
  • reduction(operation : variable): Each thread will get a private copy of variable and combine at the end with the operation.
